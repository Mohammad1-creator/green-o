# green-o: نظام إدارة المصنع

نظام عربي بالكامل (من اليمين لليسار) لإدارة مصنع: لوحة إدارة للكمبيوتر، وتطبيق جوال (PWA) للموظفين على آيفون وأندرويد.

- **المستخدمون والأقسام والفرق** بأربعة أدوار: المدير العام، ومدير الصيانة، ومدير الإنتاج، والموظف.
- **المهام** بإغلاق على مرحلتين (الموظف ينهي، والمدير يعتمد أو يعيد مع السبب)، ومشاهدة واستلام لكل موظف، وتعليقات وصور وتذكيرات.
- **الصيانة:** الآلات، وبلاغات الأعطال، وإسناد الإصلاح (لمدير الصيانة وحده)، والصيانة الوقائية الدورية.
- **الإنتاج:** مواصفات مرنة، ومنتجات ومسارات مراحل، وأوامر تعمل مراحلها بالتوازي ضمن حدود الكميات، وعيوب لكل مرحلة.
- **الإشعارات** داخل التطبيق فوراً، وWeb Push للجوال.
- **التقارير** لكل دور، مع تصدير Excel وCSV وطباعة PDF.
- **سجل تدقيق** لا يُعدَّل ولا يُحذف، بسلسلة بصمات تُفحص كل ليلة.
- **نسخ احتياطي يومي مشفر** للقاعدة والملفات خارج Supabase.

> **الحالة:** المراحل 0 إلى 13 مبنية ومختبرة على فرع `dev`. الإطلاق ينتظر إعداد الحسابات (انظر [deploy.md](docs/deploy.md)، «ما بقي عليك») وقائمة القبول.

## التقنيات

Next.js 16 (App Router، Cache Components) · React 19 · TypeScript · Tailwind CSS 4 · shadcn/ui (Base UI) · Supabase (Postgres وRLS وAuth وStorage وRealtime وpg_cron) · Vercel · GitHub Actions

## التشغيل محلياً

المتطلبات: Node.js 24 أو أحدث، وDocker Desktop (لقاعدة Supabase محلية).

```bash
npm install
npm run supabase -- start
cp .env.example .env.local   # ثم ضع قيم: npm run supabase -- status
npm run seed:dev             # بيانات تجريبية (محلياً أو dev فقط)
npm run dev
```

ثم افتح http://localhost:3000 وادخل برقم الموظف `1000` (المدير العام) وكلمة المرور التجريبية المحلية.

## الأوامر

| الأمر | ما يفعله |
|---|---|
| `npm run dev` | تشغيل نسخة التطوير |
| `npm run build` | بناء نسخة الإنتاج |
| `npm run check` | الفحص، والأنواع، والتنسيق، واختبارات الوحدات |
| `npm run test:integration` | اختبارات الـAPI على Supabase يعمل (منها التسجيل المتزامن للكميات) |
| `npm run test:e2e` | الاختبارات الشاملة في المتصفح، بمقاسي الكمبيوتر والجوال |
| `npm run supabase -- test db` | اختبارات قاعدة البيانات (pgTAP): الصلاحيات وقواعد العمل |
| `npm run check:secrets` | بعد البناء: يتأكد أن لا مفتاح سري وصل إلى ملفات المتصفح |
| `npm run seed:dev` | بيانات تجريبية؛ يرفض العمل على قاعدة ليست محلية أو dev |
| `npm run bootstrap:admin` | أول مدير عام لمشروع جديد |
| `npm run format` | تنسيق الكود |

## سير GitHub Actions

| السير | متى | ماذا |
|---|---|---|
| CI | كل رفع إلى `dev`، وكل طلب دمج إلى `main` | الفحص والأنواع والوحدات والبناء، وgitleaks، و`npm audit`، ثم Supabase محلي: pgTAP، وفحص القاعدة، والتكامل، والاختبارات الشاملة، وتجربة نسخ احتياطي كاملة |
| Deploy | بعد CI على `dev`، وعند الدمج إلى `main` (بموافقتك) | الترحيلات أولاً، ثم نشر التطبيق |
| Backup | يومياً 00:15 بتوقيت الرياض | نسخة مشفرة للقاعدة والملفات إلى تخزين خارجي |

## الفروع

- `dev`: التطوير. كل تغيير يُرفع هنا.
- `main`: الإنتاج. يُدمج فيه بعد اعتمادك.

## قواعد الأمان

- لا مفاتيح سرية في الكود، ولا في أي متغير يبدأ بـ `NEXT_PUBLIC_`.
- الصلاحيات تُفرض في قاعدة البيانات (RLS على كل جدول، ودوال تتحقق بنفسها) وعلى الخادم، وليس بإخفاء الأزرار فقط.
- رؤوس أمان على كل صفحة، منها سياسة CSP لا تسمح للمتصفح بالاتصال إلا بالتطبيق ومشروع Supabase.
- البيانات التجريبية في بيئة التطوير فقط.
